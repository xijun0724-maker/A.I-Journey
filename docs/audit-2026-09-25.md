## 0. Premise correction (read this first, again)

The brief asks for a critique of **React components, FastAPI routes, a PostgreSQL schema, LangChain
orchestration and Pinecone/ChromaDB retrieval.** A repo-wide search for
`react|fastapi|postgres|langchain|pinecone|chromadb|sqlalchemy` returns matches **only** inside
`.agents/skills/*.md` (vendored design-skill documentation). There is no such code here.

| The brief assumes | What this repository actually contains |
| --- | --- |
| React components, hooks, state library | Vanilla ES modules; every view is `fn() -> HTML string`; hash router (`src/core/router.js`); no virtual DOM |
| FastAPI routes, Pydantic validation | No backend, no routes, no server process |
| PostgreSQL schema, migrations, SQL | `localStorage` key `journeyai.db.v1` (sync bootstrap) + IndexedDB mirror `journeyai/kv` (`src/core/idb.js`); migrations are JS functions in `src/config/settings.js` |
| LangChain / agent framework | Direct browser `fetch()` to Gemini or OpenRouter (`src/ai/client.js`); zero runtime npm dependencies |
| Pinecone / ChromaDB vector DB | Hand-written BM25 over in-browser chunk ranges (`src/domain/rag.js`), optional ONNX MiniLM re-rank, off by default (`src/domain/rag-embeddings.js`) |

So dimensions 2 and 3 of the brief are audited as **string-rendered view/state architecture** and
**browser storage, isolation and trust boundaries** — the actual surfaces that carry the same
failure modes. This is not a pedantic correction: it changes the answer. The brief's central
question — *"are LangChain and a vector DB adding unnecessary overhead?"* — is already answered by
this codebase, and the answer is worth stating positively in §7.

## 1. The Professor's Verdict

This is a disciplined, genuinely well-engineered offline-first SPA — 786 passing tests, a bounded
tool-loop agent with memoised tools and a real cancel path, citation markers validated against the
passages actually supplied, SRI on all four CDN scripts, storage that strips the API key on every
persist path, and an AI that *proposes* a plan instead of writing one — and yet **the entire
refactor it is proud of is uncommitted**: 80 modified tracked files and 14 untracked `src/` paths,
including `src/styles/`, `src/ai/agent.js`, `src/core/idb.js` and both boot scripts that
`index.html` loads as raw source, so one careless `git commit -am` deploys a shell whose modules do
not exist in the repository. The AI layer is now bounded in *iterations* but not in *time*: a
single `chat()` call re-arms its full timeout on each of three retries, which I measured burning
855–1490 ms against a 60 ms deadline, and at production values (`apiRefine` 110 s) one agent turn
can occupy ~440 s inside a ceiling that claims 120 s — with no streaming, so the student watches a
spinner and cannot tell progress from a hang. Pedagogically it has quietly become the most
interesting part of the project: the recall drill now demands production before revelation and the
plan flow hands agency back to the learner, but scaffolding never fades (the default is
answer-first `explain` for every user), the practice that would drive the fading is recorded and
never read back, and the planner still reviews *deadlines* rather than *ideas*.

## 2. AI & Architectural Takedown (prioritised)

### P0 — ship-blocking / broken in the deployed configuration

**P0-1. The refactor is uncommitted, and 14 source paths the app loads are untracked by git.**

`HEAD` tracks 59 `src/` files; the working tree needs more. Untracked, verified via
`git status --porcelain`:

```
src/ai/agent.js              src/core/idb.js              src/styles/
src/boot-fallback.js         src/theme-init.js            src/config/templates.js
src/config/standards/        src/domain/nlp/              src/domain/rag-embeddings.js
src/domain/academic-calendar.js
src/views/calendar.js        src/views/modals/academic-calendar.js
src/views/modals/calendar-config.js  src/views/modals/course-image.js
```

`index.html` (tracked) loads three of them **as raw files**: `<link rel="stylesheet"
href="src/styles/index.css">`, `<script src="src/theme-init.js">`, `<script src="src/boot-fallback.js">`,
and the module graph enters through `src/main.js` → `src/ai/index.js` → `src/ai/agent.js`,
`src/core/store.js` → `src/core/idb.js`, etc. `.github/workflows/static.yml` deploys `path: '.'` —
the checked-out tree. Whatever is not committed is not deployed, so the live site would 404 its own
stylesheet, its theme bootstrap and its load-failure diagnostic, and then fail module resolution in
`main.js`. This is precisely the outage class ARCHITECTURE.md documents (a dangling named import
blanks the page) — except that `verify` cannot catch it, because **CI only ever sees tracked files**
(P1-6).

Second half of the same hazard: `coverage/` is untracked **and absent from `.gitignore`**, and
`npm run test:coverage` runs in CI. It contains generated HTML dumps of every source file
(`coverage/src/**/*.js.html`) plus `clover.xml` and `coverage-final.json` — I hit it as noise three
times while auditing, because it defeats repo-wide search. One `git add -A` commits a full source
mirror and a machine-specific absolute path set to a public Pages repository.

**P0-2. Retry amplification makes the agent's "hard ceiling" fiction — and the stall is invisible.**

`chatWithRetry` (`src/ai/client.js:381-470`) re-arms the **full** `opts.timeout` on every attempt:

```js
const retriable = aborted || status === 429 || status === 503;
if (retriable && retryCount < maxRetries) {
  const extra = status === 503 ? 2000 : 0;
  const delay = baseDelay * Math.pow(2, retryCount) + Math.random() * 500 + extra;
  return sleep(delay).then(() => chatWithRetry(messages, opts, s, retryCount + 1, maxRetries, baseDelay));
}
```

with `maxRetries = 3` by default (`src/ai/client.js:472`) — so one `chat()` can spend four full
timeouts plus `2+4+8 s` of backoff. The agent clamps *once per turn*:

```js
// src/ai/agent.js:325-329  — the clamp is not re-evaluated per attempt
const requestTimeout = () =>
  deadline === Infinity ? baseTimeout : Math.max(1000, Math.min(baseTimeout, timeLeft()));
```

**Executed, not inferred** (§5, probe A): a `chat()` call with `timeout: 60, retries: 3,
retryDelay: 1` against a fetch stub that honours the abort signal made **4 requests in 855 ms**
(1490 ms on the first run) — 14–25× the deadline the caller set. Substituting production values
(`CFG.timeouts.apiRefine = 110 000`, `src/config/constants.js:186`) gives ~440 s + 14 s backoff for
one agent turn, inside a budget of 120 000 ms. The constants file concedes the gap in its own
comment — *"hard ceiling on a whole agent run (6 calls x 110s worst case)"* is 660 s, i.e. 11
minutes — and `429`/`503` responses are retried without reading `Retry-After`. There is no
streaming (P1-1), so none of this is observable to the student: the Stop control exists, but a
"Generate plan" that will take minutes and a request that has hung look identical.

### P1 — real defects, reachable by an ordinary user

**P1-1. No streaming, anywhere.** Confirmed by absence: no `ReadableStream`, `getReader` or
`stream:` anywhere in `src/`. `client.js` does `res.json()` and returns the whole completion.
Every tutor answer is a blind 75–110 s wait (`CFG.timeouts.apiDefault/apiAnswer`). This was open
last audit and is still open; it is now the single largest UX gap, because P0-2 makes the wait
potentially many minutes.

**P1-2. The token budget can be exceeded and the over-budget payload is sent anyway.**
`checkTokenBudget` (`src/ai/client.js:249-300`) always keeps the system prompt and the final
message and back-fills only the *middle*, then reports honestly — but `chat()` calls it and uses
`budget.messages` unconditionally, ignoring `budget.ok`:

```js
const budget = checkTokenBudget(messages, { maxChars: opts.maxChars != null ? opts.maxChars : CFG.maxChatChars });
const safeMessages = budget.messages;   // src/ai/client.js:487-490
```

**Executed** (§5, probe B): system 30 000 chars + final user 5 000 chars against
`maxChars: 20000` returns `{ ok: false, truncated: true, dropped: 0, chars: 35 032 }` — a 35 kB
payload handed straight to `fetch`. `dropped: 0` is the tell: there is nothing in the middle to
evict, and the final message is never truncated. A long document-scoped question therefore
degrades to a provider error and an offline fallback, which the student experiences as "the AI
stopped working", not "your question was too long".

**P1-3. `RAG.updateIndex`'s add-path is dead code *and* would corrupt retrieval metadata.**
`index()` builds entries carrying `docName`, `courseId` and `idx` and resolves `.text` lazily via a
getter (`src/domain/rag.js:245-300`). The incremental path writes a *different shape*:

```js
idx.byId[cid] = { id: cid, docId, start: r.start, len: r.len, text: chunkText };
//                                   ^ no docName, no courseId, no idx
```

**Executed** (§5, probe C): a chunk added through `updateIndex` yields
`{ docName: undefined, idx: undefined, courseId: undefined }` where `index()` yields
`{ docName: 'Probe Notes.pdf', idx: 0 }`. `RAG.context` would then render prompts reading
`undefined (passage NaN)`, and the scoped fallback sorts on `left.docName || ""`, silently
reordering results. The blast radius today is zero because the **only** caller passes a removal
flag — `RAG.updateIndex(id, "", true)` (`src/core/actions/courses.js:50`) — and `rag.test.js` does
not touch the function at all. So: an untested, dead branch that is a loaded gun for the next
person who adds a document incrementally. `courses.js` already filters `Store.db.chunks` itself,
so the whole function reduces to `RAG.invalidate()` (§4, Step 3).

**P1-4. API-key expiry is absolute and silent — the key dies mid-semester with no explanation.**
`src/utils/secure.js:76-84`:

```js
if (now() - entry.created > KEY_TTL_MS) { clearApiKey(provider); return ""; }
```

`created` is written once in `setApiKey` and never renewed, even though `getApiKey` dutifully
updates `entry.lastUsed` on every read — so the "last-used audit" is recorded and unused, and the
TTL is 30 days *from entry*, not from last use. For the actual user of this app (a student using it
across a term), the key silently expires around week four: `usable()` flips false, `answer()` falls
back to the extractive offline path, and every surface says only *"No API key configured"*
(`client.js:37-46`) — indistinguishable from a mistyped key, and never "your saved key expired".
Also note `getApiKey` **writes** sessionStorage on every read (write-on-read).

**P1-5. Three surfaces can disagree about which model is running.**
`normalizeGeminiModel` (`src/ai/client.js:19-34`) treats its own alias list as stale:

```js
const aliases = new Set(["gemini-2.5-flash", "gemini-3.6-flash", "gemini-2.5-pro"]);
return aliases.has(cleaned) ? CFG.gemini.model : cleaned;   // "gemini-2.5-flash"
```

`gemini-2.5-pro` is a *different capability tier*, not a stale spelling of Flash — selecting it
silently downgrades the request to Flash, and `applyProviderModel` (`src/core/actions/settings.js:31`)
**persists** that rewrite. Meanwhile the assistant pill renders the raw value — `label` is derived
from `s.model` (`src/views/assistant.js:232-248`) — while `status()` and the request builder both
report/use the normalized one (`client.js:60-62`, `client.js:331`). The accompanying test covers
`flash`, `3.6-flash` and `""` (`tests/vitest/client.test.js:110-116`) and conspicuously omits the
one entry that matters. Practical severity is bounded today (the UI only offers "Flash"), but any
imported backup or migrated setting can produce a pill that names a model the app will never call.

**P1-6. The deploy gate cannot see P0-1.** `verify` runs `npm ci`, lint, tests, coverage and build
on the **checked-out tree**, which by definition contains only tracked files. Untracked-module
breakage is therefore invisible to the gate, the build, and the test suite — the same blind spot
that let a dangling import reach production before. The build *does* print the evidence for a
related problem on every run (P2-4) and is content to exit 0.

**P1-7. The orphaned-action list is still open, and the previous list was partly wrong.**
Re-verified by emission search: `chat-clear`, `chat-plan`, `chat-source`, `chat-sources-clear` and
`chat-sources-toggle` have **zero** emissions outside the dispatch table (`src/core/actions/index.js`)
— five dead handlers. The prior audit's list also named `view`, which is a **false positive**:
`src/domain/coach.js:120,136,172,191` emits `act: "view"` dynamically, exactly the pattern the
previous pass was already burned by once (with `ask`). Orphan detection needs the same
dynamic-emission awareness the markup scan now has, or it will keep producing both kinds of error.

### P2 — architecture, performance and hygiene

**P2-1. The rendering model is still the ceiling.** 18 `innerHTML` assignment sites; the router
replaces `#viewRoot` wholesale (`src/core/router.js`); four `insertAdjacentHTML` calls in
`assistant.js`; 12 module-level `document.addEventListener` sites re-established per view rebind
(`app/*`, `views/assistant.js:808`, `views/courses.js:621,643`). Consequence: focus and scroll
position are lost on re-render, behaviour must be re-bound imperatively in `after()` hooks, and
`assistant.js` is 1 016 lines because half of it is hand-rolled UI management. This is a
*deliberate* trade (zero dependencies) and worth keeping — but it means every new interactive
surface pays a rebinding tax, and the leak class fixed last audit can recur at any of the 12 sites.

**P2-2. `style-src 'unsafe-inline'` is the last `'unsafe-inline'`, and it is self-inflicted.** The
CSP in `index.html` correctly dropped it from `script-src` and added SRI to all four CDN scripts
(§7), but views emit **90 inline `style="` attributes** (`src/views/**`), which is why
`style-src` still needs the escape hatch. Encouragingly, import validation already neutralises
`course.color` / `course.image` against CSS injection (`validateBackup`) — so the remaining work is
mechanical: move those 90 declarations into the token-based class system and delete the directive.

**P2-3. The XSS scanner is not wired to anything.** `tests/scan-id-sinks.cjs` is an untracked
"one-shot scanner" with a hard-coded `SAFE_VALS` allowlist. `vite.config.js` includes only
`tests/vitest/**/*.test.js`, so it never runs in CI or in `npm test`. Either convert it to a vitest
case inside `tests/vitest/` or delete it — as it stands it looks like coverage that does not exist.
(The underlying hygiene is decent: 272 `esc(` call sites, and `markdown.js` escapes *before*
applying markup, so its `href`/`<strong>` substitutions cannot be used to inject attributes.)

**P2-4. Code-splitting is fictional.** `src/views/calendar.js`, `courses.js` and `assistant.js` are
dynamically imported by `src/core/actions/index.js` but **also** statically imported by
`src/views/index.js`, so Rollup prints three warnings on every build and folds all three into the
307 kB entry; the "lazy chunk" is 13.56 kB. On the deployed configuration this is worse than the
dist numbers suggest: Pages serves this repo as **raw source**, so the browser fetches ~100 separate
ES modules that the service worker does not cache (it caches CDN libs and fonts only), and the
entire graph must resolve before first paint.

**P2-5. Dead code found this pass.**
`Coach.weekOf` (`src/domain/coach.js:36`) has **zero callers** in `src/` and none in `tests/` —
~8 lines. Everything else on the module is live (`logActivity` 2 callers, `weekStartDate` 2,
`dailyHours`/`dailyCapacity` 4, `currentWeek` 4, `recommendations` 1). Combine with P1-3 (dead
add-branch) and P1-7 (five orphaned handlers) for the refreshed inventory. `hasApiKey` remains
production-dead but test-covered — the previous audit's deliberate keep, unchanged.

**P2-6. Documentation has drifted again, in both directions.** `ARCHITECTURE.md` claims
**767 tests / 46 files** (actual 786/47), CSS 110.64 kB (actual 123.37), JS 275.49 + 11.57 kB
(actual 307.41 + 13.56). Its "known remaining limitations" lists the heuristic confidence widget
(P1-7) as open — but `answerConfidence` **no longer exists in `src/`**; it was replaced by
`answerProvenance` + `renderProvenance` with an explicit "provenance, not confidence" contract and
band gating on a validated citation (`src/ai/index.js:104-160`, `src/views/assistant.js:19,97`).
So the doc under-claims a shipped improvement while over-claiming the baseline. `README.md`'s test
table lists 684 tests across 39 suites and omits at least ten suites that exist (`agent`,
`index-html`, `import-a11y`, `lifecycle`, `store-idb`, `ui-state`, `tasks-todo-view`,
`views-workload-removed`, `recall`, `standards`). Fixed for `ARCHITECTURE.md` at the end of this
audit (§6); `README.md` still needs the same pass.

**P2-7. `parseJson`'s last-resort repair corrupts prose.** After a failed `JSON.parse`, it strips
trailing commas **and replaces every single quote with a double quote**
(`src/ai/client.js:135-146`). An answer containing an apostrophe in a *repairable* payload becomes
invalid or mangled. Only reachable when strict parsing already failed, so: low severity, but it is
the kind of "helpful" fallback that turns a parse failure into a wrong answer instead of a clean
error.

## 3. Pedagogical Critique

Read as instructional design, this system's problems are no longer where they were — the cheap
Deweyan wins have been taken, and what remains is the harder question of *who decides*.

**Dewey — learning by doing: present, effective, and buried.** The retrieval-practice drill is the
best teaching artefact in the codebase: `generateRecallQuestions` (`src/ai/offline.js:205`) builds
questions that provably **never contain the answer's text**, the card ships **closed**, revelation
is on demand, and `markRecallResult` (`src/views/assistant.js`) self-marks and pushes the learner
back to attempt from memory (*"Reread the passage, close it, then answer again from memory."*).
`tests/vitest/recall.test.js` documents the old failure explicitly — a drill that asked the learner
to match a question printed next to its own answer. That is a real, rare fix. Two structural
limits remain: (a) the drill is reachable **only after a chat answer**, so a student who never asks
the tutor a question — the confident, self-directed student — never practices at all; and (b) the
planner's review blocks are keyed to *deadlines* (`title: "Review: " + e.title`,
`src/domain/planner.js:65-73`), which produces spaced review of **assessments**, not of **ideas**.
The one honest justification for a study planner is that it schedules retrieval of material, and
this one schedules retrieval of paperwork.

**Vygotsky — the zone of proximal development: the scaffolding is a preference, not a scaffold.**
There are three guidance levels (`explain` / `socratic` / `hint`) and they are genuinely different
prompts with different token ceilings (`answer()`, `src/ai/index.js:170-186`). But the level is a
**Settings dropdown** whose default is `explain` (`src/ai/index.js:173`, `src/views/settings.js:99`)
— answer-first, 1 024 tokens — for a first-year and a final-year student alike, forever. Nothing
withdraws support as competence grows, which is the definition of a scaffold rather than a crutch.
The worst part is that **the data needed to fade it is already being recorded and never read**:
`markRecallResult` knows hit-or-miss per passage, `Coach.logActivity` records minutes and
completion, and no code path consults either when choosing a guidance level or ordering plan
blocks. The infrastructure for adaptive fading exists; only the wiring is missing.

**Who holds agency: the AI proposes, the student decides — keep this, extend it.** The strongest
design decision in the project is that the study-plan agent authors **narrative only**. The blocks
come from deterministic `Planner.generateInteractive`, nothing is written until the student accepts,
per-task exclusion and rejection are supported, and the card carries provenance — mode, model, tool
names, call count, and *"not by an AI"* when the offline planner drafted it
(`src/ai/index.js:253-282`, `src/utils/format.js:196-200`). An agent that could write its own plan
would be a system that overpowers the learning objective; this one negotiates. The same discipline
has not yet reached the tutor: by default it still returns a finished answer to any question, so
the productive struggle is opt-in via a settings dropdown most students will never open.

**Where it still fails the learner.** (1) Practice is opt-in and post-hoc, so the learners who need
it most (those who don't ask questions) get none. (2) Guidance never fades, so the system trains
dependence by default regardless of demonstrated competence. (3) A course-specific question with no
retrieval hits still yields a fluent, general-knowledge answer; the prompt instructs the model to
say it is not from the student's materials (`src/ai/prompts.js:77`), and provenance marks it
`ungrounded` — honest, but the *text* still reads like an answer, and a student skimming will take
the prose over the band. (4) The one number the UI shows about an answer is deliberately not a
confidence score (§7) — correct — but that leaves the learner with no signal about whether *their
own* understanding is improving: `activity[]` records effort, never mastery.

## 4. The Refactoring Roadmap

Ordered by risk retired per unit of effort. Steps 1–3 are the ones I would do before any feature
work.

### Step 1 — Make the repository match the working tree, and make CI able to notice when it doesn't (30 min)

```bash
# 1. stop the coverage dump from ever being committable
printf '\n# Test output\ncoverage/\n' >> .gitignore

# 2. see exactly what a whole-tree commit would add, then commit deliberately
git add -A --dry-run | tail -20
git add -A && git commit -m "Checkpoint the AI, planner, calendar and IDB refactor"
```

Then close the hole that makes this possible, because a committed tree can drift again the moment
someone adds a module:

```js
// tests/vitest/tracked-modules.test.js — fails when the app imports a file git doesn't track
import { describe, it, expect } from "vitest";
import { execFileSync } from "node:child_process";
import { readFileSync, existsSync } from "node:fs";

const tracked = new Set(
  execFileSync("git", ["ls-files"], { encoding: "utf8" }).split("\n").filter(Boolean),
);

/** Every src/... path referenced by static import, dynamic import, <script> or <link>. */
function referenced() {
  const found = new Set();
  const walk = (rel) => {
    if (found.has(rel) || !existsSync(rel)) return;
    found.add(rel);
    const src = readFileSync(rel, "utf8");
    for (const m of src.matchAll(/from\s+["']([^"']+)["']|import\(\s*["']([^"']+)["']\s*\)/g)) {
      const spec = m[1] || m[2];
      if (spec.startsWith(".")) walk(new URL(spec, "file://" + rel).pathname.slice(1));
    }
  };
  walk("src/main.js");
  for (const m of readFileSync("index.html", "utf8").matchAll(/(?:src|href)="(src\/[^"]+)"/g)) {
    found.add(m[1]);
  }
  return found;
}

describe("every module the app loads is tracked by git", () => {
  it("has no untracked source in the load graph", () => {
    const missing = [...referenced()].filter((rel) => !tracked.has(rel));
    expect(missing, "imported but untracked: " + missing.join(", ")).toEqual([]);
  });
});
```

This test would fail on today's tree with exactly the 14 paths in P0-1, and it is the only guard
that can see the failure `verify` is structurally blind to.

### Step 2 — One deadline for a whole request, honoured by every retry (1 h)

```js
// src/ai/client.js — thread an absolute deadline instead of a per-attempt timeout
function chatWithRetry(messages, opts, s, retryCount, maxRetries, baseDelay, deadline) {
  const remaining = deadline - Date.now();
  if (remaining <= 0) {
    return Promise.resolve({ ok: false, error: "The request ran out of time before it was sent.",
                             timedOut: true, retryable: false });
  }
  const req = buildProviderRequest(messages, opts, s);
  /* Clamp THIS attempt, not the caller's nominal timeout. */
  const timeout = Math.min(opts.timeout || CFG.timeouts.apiDefault, remaining);
  ...
  .catch((e) => {
    const retriable = aborted || status === 429 || status === 503;
    const delay = /* honour Retry-After when the provider sent one */
      Number(e && e.retryAfter ? e.retryAfter * 1000
        : baseDelay * Math.pow(2, retryCount) + Math.random() * 500 + (status === 503 ? 2000 : 0));
    /* Never start an attempt the deadline cannot cover, and never retry a cancel. */
    const canAfford = deadline - Date.now() - delay > CFG.timeouts.minUsefulWindow;
    if (retriable && retryCount < maxRetries && canAfford) {
      return sleep(delay).then(() =>
        chatWithRetry(messages, opts, s, retryCount + 1, maxRetries, baseDelay, deadline));
    }
    ...
  });
}
```

```js
// src/ai/agent.js — hand the run's own deadline to every call
const ask = async (messages) => {
  const r = await chatFn(messages, {
    timeout: requestTimeout(),
    deadline,              // <- new: retries share the run's clock
    maxTokens: opts.maxTokens || 1024,
    signal: signal || undefined,
  });
  if (r && r.usage) calls.push(r.usage);
  return r;
};
```

Add `CFG.timeouts.minUsefulWindow: 4000` and `CFG.timeouts.maxRetryAfterMs: 5000`. With this,
`maxWallClockMs` means what its comment claims, and the worst case is bounded by one attempt
instead of four. Then make the bound *visible* (Step 6).

### Step 3 — Delete the incremental index path instead of repairing it (10 min)

```js
// src/domain/rag.js — delete RAG.updateIndex entirely (~55 lines, add-branch has no caller)
// src/core/actions/courses.js — the only call site already filtered Store.db.chunks:
- RAG.updateIndex(id, "", true);
+ RAG.invalidate();   // index() rebuilds lazily from Store.db.chunks on next search
```

Equivalent behaviour for the removal case, one fewer divergent code path, and probe C's

## 7. What is genuinely good (do not regress this)

- **The stack decision itself.** The brief asks whether LangChain and a vector DB add overhead; this
  project already answers it — no SDK, no orchestration framework, no vector service, no server, and
  retrieval that runs in-process. The cost of that decision is real (no shared key rotation, no
  server-side secrets, and an agent loop that still buffers a whole answer instead of streaming it —
  only the tutor and the planner's prose stream) but it bought determinism, testability, privacy and
  offline operation, and `offlineAnswer`/`offlineStudyPlan` mean the app is genuinely useful with no
  key at all.
- **Anti-hallucination as a first-class concern, not a prompt wish.** Citations are validated against
  the numbered sources actually supplied and stripped when they point outside the range
  (`validateCitations`/`sanitizeCitations`); the lowest provenance band is the honest default; an
  answer with no validated citation can never earn `grounded`.
- **A bounded, injectable agent.** Tools memoised per run with a deterministic argument key,
  repeat-detection, `maxToolResultChars`, per-run usage aggregation, cancellation that is terminal
  and never retried, and explicit degradation to the offline plan.
- **Storage discipline.** `stripKey` on every persist path, schema migrations with forward-version
  quarantine that refuses to overwrite newer bytes, dedupe-on-load, and an explicit storage-pressure
  message.
- **A test suite that earns its name** — 889 tests over 55 files including DOM behaviour, migration
  paths, agent contracts, RAG ranking, contrast math, the markup/action consistency scan, the CSP
  policy and the SSE frame reader. Its genuine gap is the *seam*, not the volume: the last two
  production-breaking bugs in this project's history lived in untested seams, which is why
  `tests/vitest/doc-removal.test.js` primes the BM25 cache before deleting — the exact sequence that
  used to leave a deleted document scoring — `tests/vitest/csp.test.js` reads the policy rather than
  the markup that produced it, and `tests/vitest/streaming.test.js` drives a transport that splits a
  frame mid-line and a 429 that lands after a delta was already shown. The newest case is
  `tests/vitest/planner.test.js` ordering two `Review:` blocks by drill history while their due
  dates point the other way: the feature is a four-hop chain (card → `byDoc` → unit → plan item)
  and no single hop asserted it.
- **Fixed since the last audit:** SRI on every CDN script, `'unsafe-inline'` out of `script-src`
  **and** `style-src`, retrieval practice that withholds its answer, an AI plan flow that proposes
  instead of writes, and token streaming for the tutor and the planner's prose.
